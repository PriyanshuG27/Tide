1. Project Overview & Laboratory Context

1.1 What is the Laboratory Integrity Dilemma?

Engineering laboratory examinations in Computer Science and Networking face a unique architectural contradiction: students must legitimately utilize native desktop development and analysis tools — including Visual Studio Code, Code::Blocks, GCC compilers, Command Prompts, Wireshark, VMware, and Packet Tracer. However, modern generative AI assistants (ChatGPT, Claude, Copilot, DeepSeek) and unmonitored local network connectivity render traditional academic assessment vulnerable to widespread dishonesty.

Existing commercial lock-down browsers (Respondus, Safe Exam Browser) enforce integrity by locking the OS into a single sandboxed browser window. In computer science labs, this model is completely unusable because students cannot write, compile, or inspect network frames from inside a web browser. Consequently, institutions historically rely on physical cable disconnection: "unplug the LAN cable".

1.2 The Day-to-Day Problem in Engineering Labs

A typical examination involves ~60 students and a single human invigilator. Physical cable disconnection fails reliably:

  • Secret Re-plugging & Hotspots: Students plug the Ethernet cable back in when the proctor looks away, or associate with unauthorized mobile Wi-Fi hotspots and USB tethering.
  • Pre-Exam Question Leaks: Questions hosted on Google Classroom, LMS, or webmail are downloaded prior to cable pulling, allowing students to obtain solutions beforehand.
  • Reusing Pre-written Code: Students access past assignments or solutions already present on the local hard drive or USB thumb drives.
  • Ad-Hoc Peer Sharing: Students spawn local HTTP servers (python -m http.server) or Netcat listeners to transmit source code directly across the room.

1.3 Our Solution — Tide

Tide (Test Integrity in Developer Environments) shifts the paradigm from rigid desktop lockdown to active network and OS-level edge monitoring with centralized telemetry. It runs a lightweight agent on each PC and a coordinator server on the teacher's machine.

Pillar Architectural Description
Native Tool Freedom Students retain unconstrained access to VS Code, Wireshark, terminals, and compilers. No kiosk editor.
Internet: Monitored By default, network connectivity remains enabled. Prohibited sites close within milliseconds at the edge.
Zero-Config Discovery Agents auto-pair with the teacher laptop over UDP broadcast (Port 47800) without manual IP typing.
Evidence Over Accusation Every alert carries timestamped telemetry, process ID, confidence score, and primary screen evidence.

4. Network Transport & Zero-Config Discovery (UDP Broadcast)

4.1 Transport Selection: Why UDP over TCP for Discovery?

In a laboratory of 60 machines, requiring students or lab administrators to manually look up and enter the teacher's current IP address is error-prone. To automate pairing, Tide implements a zero-configuration service discovery mechanism.

Why UDP was selected:

  • Broadcast Capability: TCP is strictly point-to-point and connection-oriented; it cannot broadcast. UDP natively supports broadcasting to the local subnet.
  • Connectionless Zero-Handshake: Discovery requires a single query and response. Establishing a 3-way TCP handshake to an unknown server IP is mathematically impossible.
  • Minimal Overhead: An 8-byte UDP header avoids unnecessary protocol complexity.

4.2 Limited Broadcast & RFC 919 / 922 Compliance

Tide uses IPv4 Limited Broadcast (255.255.255.255) targeting UDP Port 47800. Under RFC 919/922, packets addressed to 255.255.255.255 are delivered to all network interfaces on the local broadcast domain (the lab Ethernet switch), but are strictly prohibited from being forwarded by routers. This guarantees that student broadcasts remain confined to the specific lab room and do not leak into the wider university network.

5. Full-Duplex Telemetry Streaming (WebSocket Protocol RFC 6455)

5.1 Why Replace HTTP Polling with WebSockets?

HTTP request-response polling introduces severe network overhead and latency. For 60 concurrent seats polling every second:

  • Header Waste: Each HTTP request/response transmits ~800 bytes of headers, consuming 480 KB/s of pure header waste across the room.
  • Lack of Server Push: If an invigilator broadcasts an announcement, extends time, or triggers an emergency tab close, HTTP polling introduces latency proportional to the polling interval.
  • RFC 6455 Solution: WebSockets establish a persistent full-duplex TCP stream with a minimal 2-to-10 byte framing overhead, enabling instantaneous bidirectional message delivery.

5.2 Session Management & 256-bit Token Authentication

Upon pairing via POST /api/pair, the server generates a cryptographically secure 256-bit URL-safe token: Token = secrets.token_urlsafe(32) The server stores the token as a SHA-256 hash (hashlib.sha256). During the WebSocket opening handshake on /ws/agent, the agent must transmit a hello frame containing this token within 5 seconds. Any mismatch results in immediate termination with custom WebSocket close code 4401 (Unauthorized).

5.3 Outbox Store-and-Forward Pattern & Exponential Backoff

If Wi-Fi drops, telemetry events are queued to a thread-safe disk spool file (outbox.py). Upon reconnection, the agent executes outbox.drain(), delivering buffered events in FIFO sequence. Reconnection attempts follow truncated exponential backoff: Tbackoff = min(1.0 × 2n, 5.0) seconds.

6. Distributed Clock Synchronization (Cristian's Algorithm)

6.1 The Problem of Clock Drift in Networked Labs

In distributed lab environments, hardware clocks drift due to temperature and CPU load. A student could alter their local Windows clock backwards by 30 minutes to gain extra exam time. Furthermore, NTP (UDP port 123) is frequently blocked on isolated lab subnets.

6.2 Mathematical Derivation of Cristian's Algorithm

Tide implements Cristian's Algorithm (1989) during the initial WebSocket handshake: 

      STUDENT AGENT (Client)                      TEACHER LAPTOP (Server)
       Local Time: T_0
              │
              │────── Request (hello, local_time=T_0) ─────►
              │                                             │
              │                                     Server Time: T_server
              │                                             │
              │◄───── Reply (welcome, server_time=T_server) ─│
              │
       Local Time: T_1

Step-by-step mathematical formulation:

  1. The agent records its local monotonic timestamp T0 (sent = time.time()) in the hello frame.
  2. The server stamps its authoritative master clock time Tserver in the welcome reply.
  3. The agent notes the local arrival timestamp T1 (received = time.time()).
  4. Round-Trip Time (RTT): RTT = T1 − T0.
  5. Symmetric Delay Assumption: Assuming propagation delay is roughly equal in both directions: Tpropagation ≈ RTT / 2 = (T1 − T0) / 2
  6. Clock Offset (θ) Computation: θ = Tserver − (T0 + RTT / 2) = Tserver − (T0 + T1) / 2
  7. Authoritative Time Conversion: For all subsequent exam countdowns: Tauthoritative = Tlocal + θ

7. Cross-Layer Socket Inspection & Rogue LAN Peer Detection

7.1 The Threat of Ad-Hoc Peer-to-Peer File Shares

A common cheating method in programming labs is setting up ad-hoc local network shares — such as launching an embedded Python server (python -m http.server 8000), running Netcat pipes, or connecting via Windows SMB shares. Students can exchange code across the room without using the internet.

7.2 Transport-to-Network Cross-Layer Inspection Algorithm

Tide implements cross-layer socket table inspection in agent/tide_agent/win/net.py: 

def lan_peers(server_ip: str) -> list[Peer]:
    peers = []
    for c in psutil.net_connections("inet"):
        if c.status != psutil.CONN_ESTABLISHED or not c.raddr:
            continue
        ip = c.raddr.ip
        try:
            addr = ipaddress.ip_address(ip)
        except ValueError:
            continue
        # Verify: Private IP + Non-Loopback + Not Teacher Server IP
        if addr.is_private and not addr.is_loopback and ip != server_ip:
            proc_name = psutil.Process(c.pid).name() if c.pid else ""
            peers.append(Peer(ip, c.raddr.port, proc_name))
    return peers

7.3 Promiscuous Mode Compatibility (Wireshark Support)

A critical requirement for Computer Networks labs is that students must be able to use Wireshark. Wireshark captures network packets by placing the NIC into promiscuous mode using Npcap/WinPcap kernel drivers. Promiscuous packet capturing operates at Layer 2 and Layer 3, reading raw Ethernet frames directly. It does not create an ESTABLISHED TCP socket in the operating system's connection table. Because Tide specifically evaluates Layer 4 CONN_ESTABLISHED states, Wireshark runs without generating false alarms.

8. Active Dual-Engine Internet Probing & NCSI Captive Portals

8.1 Why Physical Link State is Deceptive

Checking whether a network adapter shows "Link Up" is insufficient. An Ethernet cable connected to a local switch shows active link state even when the lab default gateway has zero WAN connectivity.

8.2 The Dual-Engine Concurrent Probe Architecture

Tide deploys two concurrent probes executed in parallel worker threads (ThreadPoolExecutor(max_workers=2)) every 5 seconds:

Probe Engine Protocol & Target Network Verification Role
Layer 7 HTTP Probe HTTP GET to msftconnecttest.com/connecttest.txt Validates outbound HTTP routing and expects "Microsoft Connect Test". Catches captive portals (which return HTTP 200/302 redirects containing HTML login pages).
Layer 4 TCP Probe Raw TCP handshake to 1.1.1.1:443 Initiates a 3-way handshake to Cloudflare's Anycast IP. Validates Layer 4 IP routing independent of local DNS failures.
Fast Failover: Both probes use aggressive 1.5-second timeouts. If either succeeds, internet is confirmed. If an offline PC has no connection, both threads timeout within 1.5s, incurring minimal CPU overhead.

9. Payload Content Verification (Winnowing Fingerprinting)

9.1 Stopping Pre-Exam & Network-Shared Code Re-use

To prevent students from copying pre-existing lab solutions from disk or shared network drives, Tide implements the Winnowing Algorithm (MOSS-style) in common/tide_common/fingerprint.py.

9.2 Algorithmic Workflow

  1. Lexical Normalization: Strips all single-line (//, #) and multi-line (/* */) comments and condenses whitespace.
  2. Token Transformation: Language keywords (int, while, return, socket) are retained; user identifiers are replaced with generic token "v".
  3. k-gram Polynomial Hashing: Computes CRC32 polynomial checksums (zlib.crc32) over sliding windows of k tokens (k = 5).
  4. Winnowing Hash Reduction: Across every window of w hashes (w = 4), the minimum hash is selected, forming a condensed fingerprint set invariant to variable renaming.

9.3 Similarity Benchmark: Winnowing vs. Naive Matching
